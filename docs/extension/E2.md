# Этап E2 — подключение и честный статус

Состояние: 27 сентября 2026 года, выполнен. Подробные правила и словарь статусов — [SPEC.md](SPEC.md).

## Что сделано

1. **Подключение без `.env`.** `lib/ingestTokenStore.js` хранит токен в `output/.ingest-token` (атомарная запись, `wx` + права 0600; на Windows права наследуются от папки пользователя). `INGEST_TOKEN` из `.env` имеет приоритет: пока он задан, dashboard не создаёт и не удаляет токен (`409 ENV_TOKEN`). `lib/localSecurity.js` читает токен при каждом запросе, поэтому подключение и отключение действуют без перезапуска сервера. Эндпоинты `pair` / `token` / `unpair` доступны только с dashboard session; расширение подключить само себя не может (403).
2. **Раздел Health → Capture extension** (`ExtensionConnection.jsx`): `Connect extension`, токен с `Copy` / `Hide` и шагами для popup, `Show token`, `Disconnect` через диалог, строка «Extension · <состояние> · last signal N s ago · vN». Кнопка `Connect extension` в popover статуса открывает Health сразу на этом разделе и переводит на него фокус.
3. **Heartbeat.** `POST /api/extension/heartbeat` (Bearer + origin расширения, CORS-preflight разрешён) принимает `listenerState`, счётчики очереди, `pausedReason`, версию; сервер проверяет значения, считает связь живой 45 с и сам оповещает dashboard, когда она пропала. Расширение шлёт heartbeat только при наличии токена и не чаще необходимого (см. SPEC §2); закрытие DevTools сообщается сразу (`pagehide` → `DEVTOOLS_CLOSED`). Ошибка heartbeat (401/5xx) сразу видна в popup — ещё до первого захвата.
4. **Единый словарь.** `frontend/src/lib/captureModel.js` описывает статус захвата по приоритету: нет подключения → бюджет → ошибка доставки → свежий heartbeat → `Last asset accepted` / `Awaiting DevTools`. Тексты слушателя совпадают с `extension/shared/statusText.js` — это проверяет тест.
5. **Popup:** поле `Connection token` с подсказкой, откуда его взять; генерация токена для `.env` убрана в свёрнутый раздел `Advanced`; после сохранения popup сразу говорит, принял ли сервер токен. Расширение больше не создаёт токен при установке — существующие токены сохраняются.
6. **Шапка dashboard.** Подписи статуса стали длиннее, и проверка нашла горизонтальное переполнение, частично давнее: `Awaiting DevTools` переполнял шапку на 640 и 860 px, а e2e это не ловили, потому что там всегда `Manual`. Теперь на ширине < 1024 px префикс `Local ·` скрыт, подпись ограничена 128 px (< 760 px — 100 px) с многоточием. Для состояний слушателя в шапке используются короткие формы (`Watching`, `DevTools closed`). Проверено на 320/390/639/640/759/760/860/960/1023/1024/1280/1440 px, в том числе с самой длинной подписью: переполнения нет.
7. Документация: README (настройка, эндпоинты), `ACCOUNT_SAFETY.md`, `.env.example`, новая `SPEC.md`.

## Ограничения

- На Windows права 0600 не применяются, токен защищён правами папки пользователя. Главная защита — loopback, dashboard session и origin-проверки.
- Свежесть heartbeat зависит от MV3 service worker: без открытого DevTools расширение шлёт сигнал раз в минуту, поэтому после закрытия Chrome dashboard показывает «нет сигнала» в пределах ~45–60 с.
