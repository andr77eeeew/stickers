# Этап E6 — проверка и выпуск

Состояние: 27 сентября 2026 года. Автоматическая часть выполнена; ручная приёмка на тестовом аккаунте — по чек-листу [ACCEPTANCE.md](ACCEPTANCE.md), ждёт пользователя.

## Главный вывод

Всё, что можно проверить без настоящей вкладки TikTok, теперь проверяется автоматически в трёх слоях:
- логика service worker — unit-тесты с мок-сервером;
- контракт расширения с настоящим `server.js`;
- вёрстка и поведение настоящих страниц popup и панели в headless Chrome.

Открытыми остаются только вопросы, на которые отвечает живой Chrome: определение сайта через `getResources`, заголовки `no-cache` от «Disable cache», тема панели при «System preference», маркеры проверки TikTok.

## Что сделано

1. **Контракт «расширение ↔ сервер»** (`test/extension-server-contract.test.js`). Service worker из vm-harness доставляет в `server.js`, запущенный в песочнице с `SESSION_MAX_CAPTURES=2`. Harness получил режим `upstream`: запросы на loopback уходят на настоящий сервер с origin расширения. Проверяется:
   - третий захват становится `paused`, а не `blocked` и не теряется; сервер отвечает 429 с `budgetExhausted`, статус расширения — `Online`, предупреждение `session_limit`;
   - dashboard получает задержанный захват через heartbeat и не показывает ошибку доставки;
   - после **Start new session** проверка сервера возобновляет доставку, в библиотеке 3 стикера;
   - байты, которые проходят проверку расширения, но не декодируются сервером, блокируются в очереди и видны в dashboard как отказ (`lastRejectedReason`), а не как `Delivery failed`;
   - после **Disconnect** в dashboard расширение показывает `capture_disabled`, а не «Token rejected» или `Offline`;
   - все запросы идут только на `127.0.0.1:3001/api/…`; токена нет ни в статусе, который читают страницы, ни в выводе сервера.
2. **UI smoke popup и панели** (`test/e2e/extension-ui.e2e.js`, входит в `npm run test:e2e`). Настоящие `popup.html` и `panel.html` отдаются из `extension/` на фиктивном origin, `chrome.*` подставляется до загрузки скриптов. Любой запрос за пределы файлов расширения прерывается и считается ошибкой.
   - **Popup, 6 состояний:** `Not connected`, `Capture off`, `Watching`, `Session limit`, `Delivery failed`, `Verification check`. Для каждого проверяется:
     - pill и его тон;
     - ширина 360 px, светлый фон, отсутствие горизонтального переполнения;
     - у каждого поля есть label, у каждой кнопки — текст;
     - раскрытие настроек только для Connect;
     - задержанные захваты и не больше двух предупреждений.
   - **Сценарии popup:** Connect с вставкой токена, переключатель захвата с клавиатуры (Space) и focus-ring из токена, двухшаговое удаление (первый клик ничего не удаляет).
   - **Панель:** светлая и тёмная тема на 480 и 1000 px — тема по `themeName`, фон из токенов, 4 плитки, 3 предупреждения, лента, ссылка `Open in library` на loopback.
   - **Capture from Network log** в настоящем Chrome: из двух записей журнала в очередь уходит только стикер, query вырезан, миниатюра создана через `createImageBitmap` и укладывается в лимит, итог показан.
3. **Помощники тестов:** `startSandboxServer` принимает `env` и собирает вывод сервера; `loadBackground` принимает `upstream`.
4. **Исправление, найденное при подготовке приёмки:** после успешного **Connect** блок настроек в popup оставался раскрытым. Теперь он сворачивается; это проверяет e2e.
5. **Чек-лист ручной приёмки** [ACCEPTANCE.md](ACCEPTANCE.md): установка и подключение, тема панели, статический и анимированный стикер, повтор, Network log, другой сайт, отсутствие лишних запросов (service worker и вкладка TikTok), `Disable cache`, необязательная проверка бюджета, таблица отчёта. README ссылается на него.

## Ограничения

- Ручная приёмка не выполнена: нужен тестовый аккаунт TikTok и загрузка unpacked-расширения. Её результаты закроют открытые вопросы E4/E5.
- Установленный Chrome не загружает unpacked-расширения из командной строки, поэтому e2e проверяет страницы с подставным `chrome.*`, а не установленное расширение. Сам manifest проверяют unit-тесты; что Chrome принимает его без ошибок, подтверждает пункт 1.1 чек-листа.
