# Безопасность аккаунта и приватность

## Короткий вывод

Самый безопасный режим проекта — **ручной импорт локальных файлов**. В нём приложение не открывает TikTok, не использует аккаунт и не отправляет запросы к TikTok/CDN.

Опциональный DevTools live-capture уменьшает технический след относительно прежнего CDP/DOM подхода, но **не является ban-safe**. Нельзя гарантировать, что TikTok не распознает или не накажет такое использование. Правила сервиса могут запрещать неавторизованное автоматизированное извлечение независимо от количества запросов.

## Режимы и остаточный риск

| Режим | Что делает приложение | Дополнительный TikTok/CDN трафик | Рекомендация |
|---|---|---:|---|
| Manual import | Обрабатывает выбранные локальные media files | Нет | Режим по умолчанию |
| Sanitized HAR capability-test | Локально проверяет вручную экспортированный файл | Нет | Только небольшой тест; полноценная поддержка пока не подтверждена |
| DevTools network body | Читает тело уже завершённого ответа через открытую DevTools panel | Не должен создавать | Только осознанный opt-in; остаточный account/policy risk |
| Background/Node refetch | Повторно скачивает CDN asset | Да | Запрещён архитектурой |
| CDP/remote-debugging/DOM automation | Подключает debugger либо управляет страницей | Может отличаться | Удалён из штатного проекта |

## Что на самом деле влияет на риск

Расширение не создаёт трафика к TikTok и не трогает страницу, поэтому главный риск лежит в поведении аккаунта и браузера, а не в коде расширения:

| Фактор | Почему важен | Что делать |
|---|---|---|
| Открытый DevTools | Страница может заметить открытые инструменты разработчика — например, по изменившемуся размеру окна при пристыкованной панели. Расширение это скрыть не может и не пытается | Откройте DevTools отдельным окном (⋮ → Dock side → Undock); держите его открытым только во время короткой сессии |
| Быстрая прокрутка длинной истории | Массовая подгрузка сотен стикеров за минуты не похожа на обычное чтение чата | Листайте в обычном темпе; делайте перерывы |
| Перезагрузки чата ради повторного захвата | Каждая перезагрузка заново скачивает всё содержимое | Пропущенное забирайте кнопкой **Capture from Network log** |
| DevTools «Disable cache» или жёсткая перезагрузка | Все стикеры скачиваются заново при каждом показе | Держите «Disable cache» выключенным |
| Проверка TikTok (CAPTCHA), rate-limit, предупреждения | Явный сигнал, что сервис заметил необычную активность | Сразу остановитесь, закройте DevTools и пользуйтесь TikTok как обычно |

Жёсткий бюджет сессии сервера (`SESSION_MAX_CAPTURES`, `SESSION_MAX_MS`; по умолчанию 25 новых стикеров за 20 минут) сам по себе не снижает трафик к TikTok — он ограничивает только приём на localhost. Его польза — напоминание о длине сессии. При исчерпании доставка ставится на паузу без потери данных; новая сессия начинается кнопкой **Start new session** в dashboard после перерыва.

## Что расширение замечает само

Эти сигналы берутся только из метаданных DevTools, которые расширение и так видит: без новых запросов, без чтения страницы и без сохранения URL.

| Сигнал | Как распознаётся | Реакция |
|---|---|---|
| Проверка TikTok | На вкладке TikTok загружается ресурс со словом `captcha` в адресе или с хоста `verification…` | Захват **выключается автоматически**; предупреждение 30 минут в панели, popup и dashboard |
| «Disable cache» / жёсткая перезагрузка | Запросы стикеров идут с `Pragma: no-cache` или `Cache-Control: no-cache` | Предупреждение на 10 минут |
| Частые перезагрузки вкладки | 3 и больше загрузок страницы TikTok за 10 минут | Предупреждение |
| Слишком быстрая подгрузка | 12 и больше новых стикеров за 2 минуты | Предупреждение |
| Конец сессии | 80 % бюджета по числу или времени; затем исчерпание | Предупреждение; затем пауза доставки |

Счётчик и таймер сессии видны в панели **Sticker Capture**, в popup и в popover статуса dashboard. Там же — памятка безопасного захвата.

Чего расширение **не может**: скрыть открытый DevTools, определить, пристыкован ли он, увидеть предупреждения, показанные только текстом в интерфейсе TikTok, или гарантировать, что аккаунт не будет ограничен.

## Почему DevTools-поток мягче прежнего

Расширение:

- не содержит content script или MutationObserver;
- не читает DOM и не изменяет интерфейс TikTok;
- не кликает, не скроллит и не загружает историю;
- не имеет `debugger`, `tabs` или `webRequest` permissions;
- не выполняет `fetch` к TikTok/CDN;
- читает только response body, уже доступный в `chrome.devtools.network`;
- отправляет данные только на `127.0.0.1:3001`/`localhost:3001`;
- сохраняет не подтверждённую localhost-доставку в durable queue и повторяет только локальную отправку;
- не имеет `content_scripts`, `web_accessible_resources` и `externally_connectable`, поэтому страница не может обнаружить его пробой ресурсов или сообщениями.

Эти свойства проверяются тестами `test/extension/safety-invariants.test.js`: изменение, которое добавит разрешение, запрос к TikTok или доступ к странице, уронит `npm test`.

Чтобы DevTools API увидел ответ, DevTools должен быть открыт на вкладке TikTok до загрузки стикера; выбирать панель **Sticker Capture** не обязательно. На вкладках других сайтов расширение тела ответов не читает. Backend не может достоверно проверить, открыт ли DevTools: состояние listener смотрите в popup расширения.

Эти ограничения уменьшают активный технический след, но не дают гарантии безопасности аккаунта и не отменяют правила TikTok.

## Безопасная настройка localhost

1. Сервер должен слушать только `127.0.0.1`, не `0.0.0.0`.
2. Не пробрасывайте порт 3001 через router, tunnel, reverse proxy или firewall rule.
3. Dashboard сначала получает HttpOnly `SameSite=Strict` session cookie через `GET /api/session`; WebSocket `/ws` открывается только после этого.
4. Для расширения обязателен отдельный длинный токен:

   - создайте его в dashboard (**Health → Capture extension → Connect extension**) и вставьте в popup расширения; сервер хранит его в `output/.ingest-token` с правами только для владельца;
   - либо задайте `INGEST_TOKEN` в локальном `.env` (он имеет приоритет) и перезапустите backend;
   - токен не попадает в `/api/status`, WebSocket и archive snapshots; **Disconnect** отзывает его;
   - не коммитьте `.env`, не вставляйте токен в issue, screenshot или HAR.

5. Popup должен показывать server `Online`, queue `Empty` и listener `Watching TikTok tab` во время live-теста.

Offline/manual dashboard продолжает работать без подключения; в этом случае extension ingest намеренно отключён.

Heartbeat расширения уходит только на localhost и содержит лишь состояние слушателя, счётчики очереди и версию расширения — без URL, байтов и данных страницы TikTok.

## Чек-лист live-теста

Перед тестом:

- используйте только аккаунт, потеря которого приемлема;
- остановитесь, если TikTok показывает CAPTCHA, challenge, rate-limit или необычное предупреждение (при CAPTCHA расширение само выключит захват);
- откройте DevTools отдельным окном и проверьте, что «Disable cache» выключен;
- не включайте старый `start-chrome.bat`, remote-debugging, CDP, Playwright или другую UI automation;
- убедитесь, что extension popup не показывает blocked queue или token mismatch.

Во время теста:

1. Запустите backend/dashboard и проверьте localhost status.
2. Откройте TikTok Messages вручную.
3. Откройте DevTools на вкладке TikTok до появления тестового стикера. Не включайте в DevTools `Disable cache`: он заставляет заново скачивать все файлы.
4. Загрузите только один статический и один анимированный тестовый стикер обычным пользовательским действием.
5. Не используйте auto-scroll, массовую прокрутку истории, автоматическую отправку или клики. Следите за разделом **Pacing** в панели: предупреждения о темпе означают, что пора остановиться.
6. В Chrome Network проверьте, что расширение не инициировало отдельный запрос к sticker CDN.
7. После теста закройте DevTools или выключите capture toggle в popup.

Если захват был выключен, используйте в панели **Capture from Network log**: она читает только ответы, уже записанные DevTools, и не создаёт запросов. Лента и миниатюры панели хранятся в памяти браузера (`chrome.storage.session`); счётчик отклонённых изображений хранит только обезличенные шаблоны путей без query и ID.

При `Local delivery failed` не перезагружайте стикер ради повторного захвата. Исправьте localhost/token: payload уже находится в локальной очереди расширения и будет повторно отправлен только на localhost.

## HAR: ограничения приватности

Sanitized HAR обычно исключает некоторые cookies/authorization headers, но всё ещё может содержать:

- подписанные URL и query parameters;
- response bodies;
- имена endpoints и timing;
- фрагменты переписки или другие персональные данные.

Поэтому:

- экспортируйте только минимальный тестовый HAR;
- храните его вне репозитория и cloud-sync каталогов;
- не загружайте HAR в сторонние сервисы;
- после локальной проверки безопасно удалите исходный HAR;
- не считайте HAR importer реализованным, пока тест не подтвердил наличие sticker response bodies.

Проект не должен выполнять сетевой fallback для отсутствующих HAR bodies.

## Archive snapshots и восстановление

**Create archive snapshot** копирует database/media files и SHA-256 manifest в `output/archives/`. Активная библиотека не очищается и не перемещается.

Перед любым ручным cleanup:

1. создайте snapshot;
2. проверьте наличие archive manifest и media;
3. остановите сервер;
4. удаляйте только явно выбранные файлы вручную.

Web API намеренно не предоставляет необратимую очистку всей библиотеки.

## Что не хранится и не передаётся

Штатный DevTools ingest не должен сохранять cookies, authorization headers, полный DM API JSON или query string подписанного CDN URL. Backend хранит только очищенный source URL/host, media metadata, content hash и локальные файлы.

Проект не отправляет данные в Telegram автоматически. Конвертированные файлы пользователь загружает вручную.

## Правовая оговорка

Это инженерная модель снижения риска, а не юридическая консультация и не обещание отсутствия блокировки. Перед использованием ознакомьтесь с актуальными правилами TikTok для региона аккаунта. Если минимальный account-risk важнее удобства, не включайте live-capture и используйте только локальный manual import или официальный пользовательский экспорт.
