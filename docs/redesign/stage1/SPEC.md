# Этап 1 — дизайн-спецификация Sticker Workspace

Статус: **редакция 2, утверждена пользователем 25 сентября 2026 года.** Первая редакция (утверждена в тот же день) задала визуальный язык №7 Specimen Catalogue и группировку стадий из №8 Production Ledger. Редакция 2 сохраняет этот язык, но меняет структуру под реальные данные библиотеки и конечную цель продукта — подготовку стикерпака для Telegram. Этот документ и [`tokens.json`](tokens.json) — источник истины для этапов 3–5 и 7. Где PNG-макеты противоречат тексту, побеждает текст.

## 0. Что изменилось в редакции 2 и почему

Сверка макетов с локальной базой (25.09.2026, 114 записей: 48 static, 66 animated; 109 `converted`, 3 `failed`, 2 `captured`) показала, что макеты опирались на вымышленные данные:

| Предпосылка макетов | Фактические данные | Следствие для UI |
| --- | --- | --- |
| Читаемые имена `003_cat_cool.png` | 114 из 114 `originalFilename` — хэши `sticker_<sha256>.webp` | Имя не является подписью плитки; стикер опознаётся по изображению и короткому ID |
| Ручные теги `cat`, `meme` на карточках | 0 ручных тегов; есть только системный `import:<исходное имя>` | Строка тегов на плитке убрана; системный тег не показывается как тег, но участвует в поиске |
| Размер файла у каждой записи | `convertedSizeBytes` записан у 14 из 109 сконвертированных; у 95 «наследных» записей нет метаданных конвертации | Размер результата измеряется сервером по файлу (§6); проверки разделяются на «проверено» и «не записано» |
| Нарезка длинной анимации — частый сценарий | Анимаций длиннее 3 с сейчас нет | Нарезка остаётся в инспекторе/редакторе, но не занимает место на плитке |
| — | У 84 из 114 исходников большая сторона < 512 px (в основном 240×240) | Инспектор предупреждает о растягивании исходника |

Главные решения редакции 2:

1. **Картинка — единственный идентификатор.** Плитка 1:1 без строки имени и тегов; только значки состояния, длительность анимации и короткий ID.
2. **Статус «готов для Telegram» важнее статуса конвертации.** Инспектор строится вокруг блока **Telegram check** с фактическими проверками.
3. **Меньше разделов.** `Processing` становится фильтром библиотеки и полосой «Needs action»; `Import` — действием в шапке и боковой панелью; `Storage` и `Archives` объединены в `Health`.
4. **Фон превью несёт смысл.** Пастельные подложки по хэшу ID заменены переключателем: нейтральный, шахматка, чат Telegram светлый, чат Telegram тёмный.
5. **Паки — основной способ организации** (этап 7): упорядоченный набор с эмодзи на каждый стикер и экспортом для ручной загрузки через @Stickers. До реализации пункт `Packs` в навигации не показывается.

Интерактивный прототип редакции 2 не хранится в Git (эмодзи-заглушки вместо стикеров); PNG-макеты первой редакции остаются референсом по типографике, отступам, цвету и компонентам Import/Health/Editor.

## 1. Что именно утверждаем

Белый каталог без маркетингового hero, «стекла», свечения, градиентных карточек и повторяющихся статистических панелей. В первом экране — поиск и сами стикеры. Цветная подложка допускается только внутри области превью и выбирается пользователем (§3), а не назначается по ID. Стадии из №8 (`captured`, `failed`, `converting`, `converted`) используются как фильтры и значки внутри одной светлой системы; состояние файлового здоровья (`health`) не подменяет статус конвертации.

## 2. Каркас, навигация и URL

- **Шапка** (60 px desktop, 56 px mobile): слева `Sticker Workspace`; навигация `Library`, `Health` (после этапа 7 — `Packs` между ними); справа кнопка состояния локального сервиса и основная кнопка `Import`. Нижней навигационной панели на mobile нет: трёх пунктов достаточно для шапки; на ширине < 640 px бренд сокращается до значка.
- **Импорт** — не страница. Кнопка `Import` открывает боковую панель (на mobile — полноэкранный лист) с dropzone, `Choose files`, флажком auto-convert и отчётом по файлам. Перетаскивание файлов в любое место окна показывает оверлей и отправляет файлы тем же путём.
- **Needs action** вместо страницы Processing: над сеткой библиотеки появляется компактная полоса, только когда есть записи `captured`, `failed` или `converted` с отсутствующим результатом. Полоса показывает раздельные счётчики и кнопку `Show`, которая включает фильтр `Needs action`.
- **Health** объединяет Storage и Archives: сводка хранилища, создание архива, пути вывода и инструкция по загрузке в Telegram.
- **DevTools** не является вкладкой. Кнопка состояния открывает popover с различимыми состояниями `Manual import`, `Awaiting opt-in DevTools`, `Last asset accepted`, `Local delivery failed`, `Budget exhausted`, `Disconnected`, сбросом бюджета и ссылкой на Health при проблемах хранилища. Поле `listening: null` **не доказывает**, что DevTools открыт; UI не пишет «Listening». Успешный ручной импорт не меняет live-status.
- **URL**: `?view=library|health`; в библиотеке `q`, `type` (`all|static|animated`), `status` (`all|ready|action|converting`), `sort` (`newest|oldest|largest`), `page`, `id` (выбранный стикер). Значения по умолчанию из URL не пишутся. Back/Forward восстанавливают вид; смена фильтра/поиска сбрасывает `page`; открытие стикера добавляет запись истории, поэтому Back на mobile закрывает детали и возвращает к прежним фильтрам. Переходы — настоящие ссылки, не кликабельные `div`. Редактор до этапа 5 остаётся модальным окном без URL.

## 3. Дизайн-система

Машинно-читаемые значения — в [`tokens.json`](tokens.json). Цветовой замок: фон и поверхности **#FFFFFF**; основной текст `#111820`, вторичный `#5D6B80`, граница `#D7DEE8`, функциональный фиолетовый `#5133D4`. Состояния — зелёный `#087A46`, янтарный `#9A5B00`, красный `#B42318`, всегда с текстом и/или пиктограммой. Контраст к белому ≥5.4:1 для обычного текста.

Типографика — системный sans-stack без сетевой загрузки: заголовок страницы 28 px desktop / 24 px mobile, секции 20 px, текст 16 px, controls и метаданные 14 px, подпись плитки 12 px. ID и числа — моноширинный стек с `tabular-nums`.

Интервалы 4/8/12/16/24/32/48 px; радиусы 8 px для плитки и управления, 12 px для панелей и диалогов. Контролы и touch targets минимум 44 px по высоте на mobile, 36–40 px допустимы на desktop для компактного тулбара при сохранении области нажатия. Focus-visible — непрерывный 3 px контур `#B8A7F5` с 2 px отступом. Анимация — только opacity/transform по 120–180 ms, без `transition: all`.

**Фон превью** — единая настройка для плиток и инспектора, сохраняется локально с версией настроек:

| Значение | Токен | Назначение |
| --- | --- | --- |
| Neutral (по умолчанию) | `previewNeutral` `#F1F3F6` | Спокойный просмотр каталога |
| Transparency | шахматка `#E4E8ED`/`#FFFFFF` | Проверка альфа-канала и краёв |
| Chat light | `previewChatLight` `#CFE0BE` | Приблизительный фон светлого чата Telegram |
| Chat dark | `previewChatDark` `#17212B` | Приблизительный фон тёмного чата Telegram: видны ореолы и тёмные контуры |

Цвета чатов приблизительные и не выдаются за точную тему Telegram. Изображение всегда `object-fit: contain`, края не обрезаются.

**`prefers-reduced-motion`**: несущественное движение отключено; анимированные стикеры в сетке показываются первым кадром (`/api/stickers/:id/frame/0`), воспроизведение — только в инспекторе по явной кнопке.

Семейства компонентов: `AppHeader`, `StatusPopover`, `SearchField`, `FilterChips`, `SegmentedControl`, `SortSelect`, `PreviewBackgroundSwitch`, `DensityToggle`, `AttentionBar`, `StickerTile`, `Pagination`, `StickerInspector`, `TelegramCheck`, `MediaPreview`, `TagEditor`, `ImportPanel`, `ImportResultRow`, `HealthSummary`, `ArchiveCard`, `ConfirmDialog`, `InlineAlert`, `Toast`. Один стиль кнопок во всех режимах, различия — вариантами. Иконки — один outline-набор (lucide) толщиной 1.75–2 px; декоративные скрыты от screen reader, иконки без текста имеют `aria-label`.

## 4. Компоновки и сценарии

### Library

- **Тулбар** (sticky под шапкой): поиск; фильтр статуса `All · Ready · Needs action` (+ `Converting`, если такие записи есть) с динамическими счётчиками; тип `All · Static · Animated` со счётчиками; сортировка; фон превью; плотность. На mobile тулбар — одна горизонтально прокручиваемая строка под полем поиска, без переноса и без горизонтального overflow страницы.
- **Определения статусов** (вычисляются из одного snapshot):
  - `Ready` — `status === 'converted'`, нет `missing_converted`, измеренный размер результата не превышает лимит Telegram (512 KiB static, 256 KiB video). Если размер не удалось измерить, запись не считается Ready.
  - `Needs action` — `captured`, `failed`, или `converted` с `missing_converted` / превышением лимита.
  - `Converting` — `status === 'converting'`.
- **Поиск** — по ID, исходному имени импорта (из системного тега `import:`) и ручным тегам. Сортировки: `Newest` (по `capturedAt`, tie-break ID), `Oldest`, `Largest output` (по измеренному размеру результата; без результата — в конце).
- **Плитка**: поле превью 1:1, под ним короткий ID (8 символов, моноширинный) и измеренный размер результата. На превью: `▶ 2.4s` для анимации (или `Animated`, если длительность неизвестна), значок состояния для всего, что не Ready (`Not converted`, `Converting…`, `Failed`, `Output missing`, `Over limit`). Имя файла и теги на плитке не выводятся. В плотном режиме подпись скрыта, остаётся превью со значками. `aria-label` плитки содержит ID, тип и состояние.
- **Сетка**: `auto-fill` с минимальной шириной плитки 132 px (comfortable) / 92 px (dense) на desktop; на mobile 3 колонки при ширине ≥ 360 px и 2 колонки уже. Gap 12 / 8 px. Первый ряд плиток начинается не ниже **200 px** от верха viewport на desktop 1440×900 и не ниже **280 px** на 390×844 (с учётом полосы Needs action).
- **Страницы**: **24 записи** на страницу (comfortable), 48 в плотном режиме; `Previous` / `Next` и `Page N of M`. Не более одной страницы в DOM. Изображения ниже первого экрана — `loading="lazy"`, размеры заданы заранее.
- **Пустые состояния**: `No stickers yet` + `Import files`; `No stickers match your search` + `Clear filters`.
- **Клавиатура**: `/` фокусирует поиск; стрелки перемещают фокус по сетке с учётом числа колонок; Enter/Space открывает стикер; Escape закрывает инспектор и возвращает фокус на плитку.

### Sticker inspector

- Desktop ≥ 1100 px: немодальная колонка 380 px справа, сетка остаётся видимой. Уже 1100 px: полноэкранный слой с кнопкой `Back`, основное действие закреплено снизу с safe-area.
- **Превью** на выбранном фоне с переключателем `Original` / `Telegram`. `Telegram` доступен при существующем `convertedPath` и отсутствии `missing_converted`; иначе вкладка выключена с пояснением `Output missing` или `Not converted yet`. Анимированный результат WebM воспроизводится через `<video muted loop playsinline>` с кнопкой паузы.
- **Telegram check** — список строк «иконка · проверка · значение», каждая строка несёт один из статусов `ok`, `warning`, `problem`, `unknown`:
  - `Format` — по расширению результата: WebP (static) или WebM (video).
  - `File size` — измеренный размер / лимит, шкала; `warning` при > 90 % лимита, `problem` при превышении или отсутствии файла.
  - `Duration` (только анимация) — из записанного диапазона конвертации; ≤ 3.0 s — `ok`; нет записи — `unknown` с текстом `Not recorded (converted by an earlier version)`.
  - `Dimensions` — `ok` с текстом `512 px, checked at conversion`, только если запись содержит метаданные текущего конвейера (`conversion`); иначе `unknown`.
  - `Source` — размеры исходника; `warning` `Upscaled N× to reach 512 px — edges may look soft`, если большая сторона < 512 / 1.5.
  - Для `captured` / `failed` вместо проверок результата — строка статуса и безопасная формулировка `sticker.error`.
- **Действия по состоянию**: основное — `Download WebP/WebM` (Ready), `Convert for Telegram` (captured), `Retry conversion` (failed), `Re-convert` (output missing). Вторичные — `Edit`, `Re-convert` для готовых. При `missing_original` конвертация и редактор выключены с объяснением; существующий результат можно скачать. Для анимации длиннее 3 s в инспекторе есть ползунок начала 3-секундного окна (как в текущей карточке).
- **Теги**: ручные теги chip-кнопками с удалением, Enter добавляет, `Save tags` применяет через `POST /api/stickers/:id/tags`. Системные `import:` теги не показываются как chips и **сохраняются** при записи. На ошибке введённые теги остаются в форме.
- **Детали**: полный ID с копированием, дата импорта, источник (`manual` / `devtools`), исходное имя импорта, размеры исходника, число кадров.

### Import panel

- Строго локально: drag/drop в любом месте окна и `Choose files` дают одинаковый результат. Поддерживаемые расширения PNG/JPG/WebP/GIF/TIFF/AVIF/MP4/WebM/MOV/MKV/M4V, до 30 файлов за раз (ограничение сервера). Флажок `Convert to Telegram format after import` по умолчанию включён, как сейчас.
- Отчёт текущего batch: счётчики `imported`, `duplicates`, `failed` из ответа API и строка на каждый файл (`Accepted`, `Duplicate`, `Failed` + причина). Общий отказ (например 413) показывается одной ошибкой над списком, без выдуманных строк. Результат живёт в памяти панели; persistent history не обещан. `Show in library` закрывает панель и сбрасывает фильтры на `Newest`.
- HAR UI не включён. Нет облачной загрузки и автоматической публикации в Telegram.

### Health

- **Storage**: сводка из `GET /api/status` — `missing original`, `missing output`, `unlinked files`, `temporary entries`, `interrupted conversions` и время последней проверки (`checkedAt`). Категории не складываются в «число повреждённых стикеров». Различаем `No issues found` и `Storage check unavailable`. Кнопка `Refresh summary` перечитывает статус и так и называется. Пока нет read-only endpoint, вместо таблицы — строка `Item-level details are not available yet`; `Missing output` и `Missing original` ведут в библиотеку с фильтром `Needs action`.
- **Archives**: `Create archive snapshot` с доступным диалогом подтверждения (не `window.confirm`); после успеха — путь и число записей из ответа сервера. Список и `Verify` — после API этапа 5, до этого строка `Archive history is not available yet`. Никакого `Restore`.
- **Output & Telegram**: серверные пути `statics`/`animated`/`archives` с `Copy path` и короткая инструкция: загрузка вручную через официальный @Stickers.

### Editor

Без изменений относительно первой редакции (реализация — этап 5): desktop — превью/кадры слева, настройки справа; mobile — превью → `Animation slice` → `Transform` → `Outline` → `Text`. Scale 0.5–2.0, rotation −180…180°, outline 1–20 px + color, top/bottom text до 100 символов. Для анимации выбирается только начало, окно ≤ 3 s. `Original` / `Telegram` переключение без потери формы; `Discard changes?` при уходе с несохранёнными правками. До этапа 5 текущий модальный редактор только перекрашивается в светлую систему без изменения поведения.

### Packs (этап 7)

- Пак — упорядоченный набор ID стикеров с названием и эмодзи для каждого стикера (Telegram требует эмодзи при добавлении стикера через @Stickers).
- Внизу библиотеки — панель черновика пака: миниатюры по порядку, число стикеров, число без эмодзи, `Open pack`, `Export for @Stickers`. В инспекторе — выбор эмодзи, который добавляет стикер в текущий пак.
- Экспорт — локальный ZIP: пронумерованные файлы в порядке пака и текстовая шпаргалка «№ → файл → эмодзи». Экспорт блокируется, пока есть стикеры без эмодзи, не Ready или смешение форматов, если оно не поддерживается выбранным типом пака. Публикация остаётся ручной; Telegram API не используется.
- Фильтр `Not in a pack` и значок эмодзи на плитке появляются вместе с этой функцией.

## 5. Состояния, тексты и переходы

| Ситуация | Что видно | Действие |
| --- | --- | --- |
| Первый запрос выполняется | Шапка и skeleton площади первых плиток, без ложных счётчиков | Дождаться; focus не прыгает |
| Пустая библиотека | `No stickers yet` и пояснение локального импорта | `Import files` |
| Поиск/фильтр без совпадений | `No stickers match your search` | `Clear filters` |
| Сервер недоступен при старте | `Can't connect to the local service`; `Your sticker files have not been changed` | `Retry connection`; подсказка запустить сервер |
| WebSocket оборван после загрузки | Записи остаются видимыми, статус `Updates paused` | Автоматический и ручной `Reconnect` |
| Импорт: частичный успех | Раздельные счётчики и строка на каждый файл | `Show in library` |
| Импорт: запрос целиком отклонён | Общая ошибка без фиктивных строк | Повторить меньшей партией |
| Сконвертирован, но output отсутствует | Значок `Output missing`; статус `converted` не переписывается | Download выключен; `Re-convert` при наличии оригинала |
| Результат превышает лимит | Значок `Over limit`, строка File size — `problem` | `Re-convert` / `Edit` |
| Original отсутствует | `Original missing` в инспекторе | Edit/convert выключены; существующий output доступен |
| Ошибка сохранения тегов | Введённые теги остаются в форме, сообщение рядом | Исправить и повторить |
| Создание архива не удалось | `Archive could not be created` + причина | Повторить |
| Storage summary недоступна | `Storage check unavailable`, а не `0 issues` | `Refresh summary` |
| DevTools не включён | `Manual import` в кнопке состояния | Подробности в popover, без ложного `Listening` |

Сообщения об ошибках — рядом с соответствующей формой/действием; transient success — через `role=status`, error — через `role=alert`, без озвучивания каждого WebSocket-события. Toast не является единственным местом важной причины сбоя. Недоступные действия не скрываются молча: объяснение остаётся текстом.

## 6. Контракт данных и граница реализации

| UI | Действующий источник | Что добавляется |
| --- | --- | --- |
| Каталог, статусы, теги, media | `GET /api/stickers`, WebSocket `init/new_sticker/sticker_update`, `POST /api/stickers/:id/tags` | **Этап 3:** вычисляемое поле `outputSizeBytes` — размер файла результата, измеренный `fs.stat` при отдаче записи; в базу не пишется, `null` при отсутствии файла |
| Telegram check | `conversion`, `convertedRange`, `durationMs`, `width`/`height` записи | Размеры результата для наследных записей — только отдельной read-only проверкой, не догадкой |
| Статус сервиса и Storage summary | `GET /api/status`, `GET /api/session` | Достоверный сигнал DevTools listening; детальная проверка файлов (этап 5) |
| Импорт | `POST /api/import/files` с `imported`, `duplicates`, `failed`, `results` | Batch/job контракт (этап 4) |
| Редактор и output | `/api/stickers/:id/frame/:frameIndex`, `/api/convert`, edit routes | Undo/history при необходимости |
| Архив | `POST /api/library/archive` | `GET /api/library/archives` и read-only verify (этап 5) |
| Паки | Отсутствуют | Отдельное атомарное хранилище метаданных паков и export endpoint (этап 7) |

Будущие endpoint-ы этапа 5: `GET /api/storage/issues`, `GET /api/library/archives`, `POST /api/library/archives/:id/verify` — все read-only, наследуют session/origin защиту и не принимают произвольный путь из UI.

## 7. Правила реализации и проверки

- Семантические `a` для переходов, `button` для действий, `label` для всех полей; `Skip to content`. Focus-visible, разумный DOM order, закрытие popover по Escape и клику вне, возврат фокуса при закрытии инспектора/диалога. Настоящий `<dialog>` для подтверждений.
- Поддержать 320, 360, 390, 640, 768, 960, 1280, 1440 px. Проверить клавиатуру, 200 % zoom, разные aspect ratio, reduced motion. Нет горизонтального overflow; закреплённые элементы не закрывают последний ряд.
- Общие UI-компоненты не знают о способе получения данных. WebSocket-обновления не сбрасывают фокус, фильтр и текущую страницу. Селекторы статусов/счётчиков выводятся из одного snapshot и покрыты unit-тестами.
- Существующие записи не оправдывают постоянный DOM из всех плиток. Виртуализация — только по замерам.
- Browser-проверка против этой спецификации: иерархия, плотность, геометрия, цвет; `npm run check`; URL navigation; keyboard-only; импорт/дубликат/частичная ошибка; static/animated convert и download; 1000-record fixture.

Правила доступности основаны на [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines); конкретные решения — проектные.
