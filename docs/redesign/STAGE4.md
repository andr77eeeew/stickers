# Этап 4 — импорт, массовые действия и центр задач

Статус: **принят пользователем 25 сентября 2026 года** с одной доработкой (подтверждение большого пакета). Поведение описано в [SPEC.md](stage1/SPEC.md), раздел «Selection & Jobs».

## Что сделано

| Область | Реализация |
| --- | --- |
| Реестр задач | `lib/jobRegistry.js`: задача с ID, состоянием каждого стикера (`queued` / `running` / `succeeded` / `failed` / `skipped` / `cancelled`) и итогом, выведенным только из этих состояний. Завершённый элемент больше не меняется. Отмена затрагивает только не начатые элементы. История ограничена 20 задачами, выполняющиеся не вытесняются |
| Сервер | Тело конвертации вынесено в `performConversion`, постановка в очередь — в `enqueueConversion`; одиночный `/api/convert` и задачи используют один ключ очереди на стикер, поэтому один ID никогда не конвертируется параллельно. Новые маршруты: `GET /api/jobs`, `POST /api/jobs/convert`, `POST /api/jobs/tags`, `POST /api/jobs/:id/cancel`, WebSocket `job_update`, `jobs` в `init`. Защита — та же dashboard-сессия |
| Пакетная конвертация | Причины пропуска определяются до постановки в очередь: «не найден», «уже в очереди в другой задаче», «нет оригинала». Лимит 100 стикеров на задачу, concurrency очереди прежняя (2). Переполнение очереди — понятная ошибка элемента |
| Пакетные теги | Добавление и удаление за один проход, одно сохранение базы; при ошибке записи все изменения откатываются. Системные `import:` теги защищены на сервере и в UI |
| Клиент | Режим выбора (Shift-диапазон, «Select page», Escape), панель выбора, диалог тегов, кнопка и боковая панель Jobs, значок `Queued` на плитках, `Convert N` в полосе Needs action (при N > 10 — диалог подтверждения), тост по завершении задачи |
| Импорт | Auto-convert — одна серверная задача вместо последовательного цикла в браузере. Строки отчёта показывают состояние конвертации каждого файла; ошибки импорта и конвертации переведены в понятные формулировки без путей |

## Проверки

- `npm run check`: 48/48 тестов, ESLint без предупреждений, сборка Vite (CSS 28.3 kB / gzip 6.4 kB, JS 226.7 kB / gzip 71.4 kB).
- Новые тесты: переходы состояний задачи, заморозка завершённых элементов, отмена только очереди, ограниченная история; интеграционный — 401 без сессии, отказ пустого и некорректного списка ID, схлопывание дубликатов, пропуск отсутствующего оригинала и неизвестного ID, `job_update` по WebSocket, итог `partial`, пакетные теги с отчётом, защита `import:`, удаление тегов, 404 отмены неизвестной задачи; клиентская модель — порядок и устаревшие обновления, счётчики очереди, тексты прогресса и ошибок, тосты.
- **Песочница** (`127.0.0.1:3003`, пустая временная библиотека, ingest выключен), сценарий приёмки: 30 файлов перетаскиванием — 27 принято, 1 дубликат, 2 повреждённых с понятными причинами; импорт ~1 s; одна задача сконвертировала 27 стикеров примерно за 14 s (очередь 2 параллельно, остальные с меткой `Queued`); тост «27 stickers converted.». Выбор страницы (24) → `Convert 24` → `Cancel 22 queued`: 2 уже запущенные завершились, 22 отменены, итог `Cancelled`. Shift-диапазон выбирает 5 плиток; пакетные теги добавлены к выбранным с сохранением `import:`; ввод `import:` блокируется. После перезагрузки страницы задачи подтягиваются с сервера; после перезапуска сервера список пуст, и панель прямо говорит об этом.
- Вёрстка: горизонтального переполнения нет на 360–1440 px с включённым режимом выбора; шапка с новой кнопкой Jobs укладывается в 320 px.

## Ограничения

- История задач живёт в памяти процесса сервера. Постоянное хранение добавлять только при реальной потребности.
- Пакетного скачивания нет: ZIP-экспорт появится вместе с паками на этапе 7.
- Одиночная конвертация из инспектора по-прежнему идёт через `/api/convert` и в Jobs не попадает; её результат виден в самом инспекторе.

## Приёмка

Принято: история задач в памяти сервера (последние 20, сброс при перезапуске). По решению пользователя `Convert N` в полосе Needs action при N > 10 сначала показывает диалог подтверждения; проверено в песочнице — отмена не создаёт задачу, подтверждение ставит одну задачу на 12 стикеров. Следующий шаг — этап 5.
