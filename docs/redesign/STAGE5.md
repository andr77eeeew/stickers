# Этап 5 — редактор, Health и архивы

Статус: **принят пользователем 25 сентября 2026 года** без изменений. Поведение описано в [SPEC.md](stage1/SPEC.md), разделы Editor и Health.

## Что сделано

| Область | Реализация |
| --- | --- |
| Редактор | Модальное окно заменено отдельным видом `?view=editor&id=…`. Превью не мигает (кэш изображений, перерисовка после загрузки), `Original` / `Telegram`, ползунки с числовыми полями и единицами, сворачиваемые Outline и Text, счётчик символов. Undo по жестам (Ctrl+Z), Reset, который тоже отменяется. `Discard changes?` для Library / Cancel / Escape, `beforeunload` для вкладки. Ошибка сохранения — понятный текст над редактором, параметры остаются |
| Анимация | Окно ≤ 3 s с одним ползунком начала, подсказки `Selected` / `Source`, короткий источник получает окно короче. Лента из 8 кадров выбирает кадр превью. Превью подписано как один кадр с приблизительными эффектами. После сохранения окно запоминается для инспектора |
| Модель | `editorModel.js` (пределы как у сервера, окно, выбор кадров), `editorHistory.js` (чистый reducer истории), `editorRender.js` (отрисовка; статичный экспорт всегда с эффектами) |
| Проверка хранилища | `POST /api/storage/check` сравнивает базу с диском и возвращает элементы по пяти категориям с относительными путями (до 500 на категорию). Меняет только флаги health |
| Исправление | Раньше каждая проверка (в том числе после любого импорта) переводила записи `converting` в `failed` как «прерванные». С пакетными задачами это ломало работающие конвертации. Теперь восстановление прерванных выполняется только при старте сервера, а флаг `interrupted_conversion` сохраняется до повторной конвертации |
| Архивы | `GET /api/library/archives` (только папки с ID нужного формата, данные из manifest) и `POST /api/library/archives/:id/verify` (потоковый пересчёт SHA-256, отчёт missing / changed / unexpected, не больше одной проверки одновременно). Ничего не пишется и не восстанавливается |
| Health UI | `Run check` со списком элементов по категориям (`Open sticker` для записей, `Review manually` для файлов), список архивов с целостностью и `Verify files`, подробности расхождений |

## Проверки

- `npm run check`: 52/52 теста, ESLint без предупреждений, сборка Vite (JS 240.5 kB / gzip 75.8 kB).
- Новые тесты: пределы параметров, окно анимации (4.8 s → 1.0–4.0 s, кадры 8–67, короткий источник), выбор кадров ленты, история Undo; проверка хранилища во время конвертации не трогает `converting`, флаг прерывания переживает повторные проверки, имена элементов относительные; интеграционный — 401 без сессии, отсутствующий оригинал и лишний файл в отчёте, проверка ничего не удаляет, архив появляется в списке, `verified` → подмена файла и лишний файл → `mismatch` без исправления, отказ на `../` и несуществующий ID.
- **Реальный архив этапа 0** проверен только на чтение прямо через модуль: 206 из 206 файлов совпадают с manifest.
- **Песочница** (`127.0.0.1:3003`): GIF 4.8 s (96 кадров) — окно `0.0–3.0 s`, после сдвига `1.0–4.0 s`; Undo отменил последний жест; Escape с правками открыл `Discard changes?`, `Keep editing` вернул в редактор; сохранение с текстом дало `animated-edit` со стартом 1.0 s и длительностью 3000 ms и вернуло в библиотеку с открытым инспектором (Telegram check: 205 KB / 256 KB, 3.0 s). Статическая правка с outline сохранена из режима `Original` (`static-edit`), таймлайна у статики нет. Health: `Run check` показал подброшенный лишний файл как `statics/2026-09-25/stray-qa.webp` с `Review manually`; архив создан через диалог и получил `Verified`.
- Вёрстка: редактор на 390 и 768 px и Health на 390 px без горизонтального переполнения.

## Ограничения

- Кнопка «назад» браузера не перехватывается диалогом `Discard changes?` — защищены кнопки редактора, Escape и закрытие вкладки.
- Превью анимации — один кадр с эффектами, отрисованными в браузере; итоговый WebM рендерит сервер (sharp), поэтому возможны мелкие отличия, о чём сказано в подписи.
- Результаты проверки архивов и история задач живут до перезапуска сервера. Восстановление архива не реализовано.

## Приёмка

Принято как есть: защиты от потери правок без перехвата кнопки «назад» браузера достаточно; результат проверки архива не сохраняется на диск — проверка выполняется по запросу. Следующий шаг — этап 6.
