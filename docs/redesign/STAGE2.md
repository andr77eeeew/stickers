# Этап 2 — структурное разделение клиента

Статус: завершён. Визуальный редизайн из [спецификации этапа 1](stage1/SPEC.md) намеренно **не** выполнялся: экран, тексты, порядок блоков и действующие API остались прежними. Новая система каталога и навигация относятся к следующим этапам.

## Структура после переноса

| Модуль | Ответственность |
| --- | --- |
| `frontend/src/App.jsx` | Сборка текущего экрана, фильтр/поиск и передача зависимостей; 193 строки вместо 1572 |
| `frontend/src/lib/api.js` | Same-origin HTTP и адрес WebSocket |
| `frontend/src/lib/stickerModel.js` | Пути медиа, длительность и сохранённый диапазон, фильтрация/счётчики/группировка, пути и health-summary |
| `frontend/src/hooks/useStickerSession.js` | Authenticated bootstrap, WebSocket init/update/status, reconnect и состояние сервиса |
| `frontend/src/hooks/useStickerActions.js` | Convert, tags, download, archive, reset capture budget и копирование пути |
| `frontend/src/hooks/useManualImport.js` | Локальный file import и опциональная последовательная auto-convert |
| `frontend/src/hooks/useStickerEditor.js` | Canvas preview, modal focus, параметры и save/edit API |
| `frontend/src/components/*` | Шапка/статус, статистика, import zone, группы карточек, editor modal |

Разделение сохраняет текущие 48 карточек на порцию. Переход на согласованные 24, URL-state, новые фильтры, новый дизайн и расширения backend **не** включены в этап 2.

## Проверки

- `npm run check`: 33/33 теста, ESLint без предупреждений, Vite build успешно. Добавлены три unit-теста для вынесенной модели библиотеки, медиа-путей и storage summary.
- Встроенный Browser на `127.0.0.1:3001`: реальная библиотека загрузилась, 48 карточек первой порции, поиск без совпадений, фильтр, открытие/закрытие редактора, без ошибок консоли и framework overlay. Никакие операции записи на этой библиотеке не выполнялись.
- Playwright CLI mobile 360×732: приложение загрузилось, 48 карточек в DOM, нет горизонтального overflow и предупреждений/ошибок консоли. Текущий высокий первый экран совпадает с прежним дизайном и остаётся задачей этапа 3.
- Отдельный сервер `127.0.0.1:3002` с уникальной пустой библиотекой в системном Temp: синтетический PNG импортирован без auto-convert, тестовый тег сохранён, статическая конвертация и сохранение через редактор завершились, архив создан. После reload сохранились одна запись, тег и статус `converted`; WebSocket подключился. Консоль успешного прогона чистая.
- Первый изолированный upload получил `EPERM` при использовании сервером стандартного `temp/uploads` в workspace-песочнице. Повторный прогон с `STICKER_TEMP_DIR` в системном Temp прошёл. Это ограничение текущей среды тестирования; код клиента не менялся для обхода.

Ручное live DevTools capture с TikTok не проверялось и не требуется для структурного этапа. Следующий шаг — этап 3: ввод утверждённого светлого каталога и responsive UX с проверкой против макетов.
