# Этап 7 — паки и экспорт для @Stickers

Статус: **принят пользователем 26 сентября 2026 года** без изменений. Загрузка пака в @Stickers по `pack.txt` остаётся в разделе «Ручная приёмка». Поведение описано в [SPEC.md](stage1/SPEC.md), раздел Packs.

## Правила Telegram

Сверены с документацией Telegram перед реализацией (25.09.2026):

- в паке до **120** стикеров (Bot API 7.0: «maximum number of stickers in any regular and mask sticker set to 120»);
- у стикера **1–20** эмодзи;
- требования к файлам не изменились: статичный WebP/PNG, одна сторона 512 px; видео — VP9 WebM без звука, до 3 s, до 30 FPS, до 256 KB;
- API допускает смешанные наборы, но официальный **@Stickers** создаёт статичные паки через `/newpack`, а видео — через `/newvideo`. Проект работает только через этого бота, поэтому пак держит один формат.

## Что сделано

| Область | Результат |
| --- | --- |
| Хранилище | `lib/packStore.js`: `output/packs.json` отдельно от базы стикеров. Запись атомарная (temp + fsync + rename), предыдущая версия лежит в `packs.backup.json`. Перед самой первой записью создаётся archive snapshot библиотеки. Повреждённый файл восстанавливается из backup, копия откладывается как `packs.corrupt-*.json`. Если оба файла нечитаемы, паки становятся read-only и файлы не перезаписываются. `revision` защищает от перезаписи из второй вкладки (409 + актуальная версия). Новые snapshots включают `packs.json` и backup |
| Валидация | Название до 64 символов; до 50 паков; до 120 стикеров; эмодзи — графемы Unicode (флаги, ZWJ-последовательности, модификаторы тона, keycap), дубликаты убираются, не больше 20. ID стикера существует или уже был в паке — запись, пропавшая из библиотеки, не исчезает из пака молча. Форматы не смешиваются |
| API | `GET/POST /api/packs`, `POST /api/packs/:id`, `/activate`, `/delete`, `GET /api/packs/:id/export`. Защита session/origin та же, что у остальных API; ID пака проверяется по шаблону. WebSocket: `packs_update` и `packs` в `init` |
| Экспорт | `lib/packExport.js` + `lib/zipWriter.js` (ZIP без сжатия, UTF-8 имена, CRC через `zlib.crc32`, без новых зависимостей). Файлы `001_<id8>.webp` … в порядке пака и `pack.txt` (UTF-8 с BOM) с командой бота, шагами и таблицей «№ → файл → эмодзи». Сервер повторно проверяет готовность; при проблемах — 409 с позициями. На диск ничего не пишется |
| Библиотека | Пункт `Packs` в шапке; панель текущего пака внизу (название, N/120, тип, миниатюры, причина блокировки, `Open pack`, `Export for @Stickers`); эмодзи текущего пака на плитке (`?` — эмодзи не выбран); фильтр `Not in a pack` (`unpacked=1`) учитывается во всех счётчиках; `Select → Add to pack` с отчётом о пропущенных |
| Инспектор | Секция Pack: форма создания; палитра из 16 эмодзи и поле для любого эмодзи — выбор добавляет в текущий пак; `#n of N`, смена эмодзи, `Remove from pack`, «Also in» |
| Экран Packs | Список паков и новый пак; переименование, `Make current`, `Delete pack` с подтверждением; строка готовности; упорядоченный список с миниатюрами-ссылками, проблемами, полем эмодзи, ↑/↓/удалить и перетаскиванием мышью; фокус остаётся на нажатой кнопке после перестановки; шаги публикации в @Stickers |
| Шапка | С третьим пунктом навигации бренд сокращается до значка ниже 860 px (было 640 px); при ≤ 359 px пункты навигации компактнее. Переполнения нет на всех ширинах 320–1440 px с шагом 20 px для Library, Packs и Health |

- `npm run check`: **63/63** тестов (+10: хранилище, эмодзи, ZIP, проблемы экспорта, API, модель клиента, URL-состояние), линт без предупреждений, сборка CSS 37.19 kB (gzip 7.88), JS 265.91 kB (gzip 83.16) — +7.4 kB gzip JS к этапу 6.

Новый `test/e2e/packs.e2e.js` проходит путь создание → эмодзи в инспекторе → значок на плитке → `Add to pack` (видео пропущено с причиной) → `Not in a pack` → эмодзи в строках и ошибка «“a” is not an emoji.» → перестановка с клавиатуры с сохранением фокуса → экспорт: разбор ZIP, порядок файлов, `pack.txt`, побайтовое совпадение с результатом конвертации → ширины 320/390/768/1440 → перезапуск сервера → удаление пака, стикеры и файлы на месте → нет ошибок консоли. Смоук и сценарий на 1000 записей по-прежнему проходят (первая плитка 0.2 s, поиск 51 ms).
- ZIP из песочницы распакован штатным `Expand-Archive` Windows: 8 файлов и `pack.txt` с корректными эмодзи.
- Реальная библиотека `D:\Projects\stickers\output` в этом этапе не открывалась на запись: `packs.json` там нет. Проверки шли на временных библиотеках.

## При первом использовании на реальной библиотеке

Первое создание пака сделает archive snapshot всей библиотеки (сейчас ~230 файлов). Это однократно и занимает секунды; snapshot виден в Health → Archives.

## Ручная приёмка

1. Создать пак, добавить ~20 статичных стикеров, выбрать эмодзи, переставить, экспортировать.
2. Открыть ZIP, в @Stickers выполнить `/newpack` и загрузить файлы по `pack.txt` (можно не публиковать — `/cancel`).
3. Проверить, что видео-стикеры предлагается собирать в отдельный пак.

Отложено: смешанные паки (если @Stickers начнёт их принимать), иконка пака, короткое имя ссылки — они задаются в самом боте.
